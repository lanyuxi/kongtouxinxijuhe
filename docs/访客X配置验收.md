# 访客 X 配置验收记录

日期：2026-10-01。本机实现与模拟 X 链路已完成；完整回归通过，独立审查提出的三项问题均已修复验证。

## 使用方法

1. 打开本地页面，点击右上角“设置”。
2. 按页面中的四步说明申请 X 开发者账号、创建应用、取得 Bearer Token，并确认额度与消费上限。
3. 粘贴访问凭据，点击“保存并检测”。后台真实检测账号查询及推文读取；通过后加密保存并自动抓取。
4. 返回列表查看“我的 X 最新动态”，项目详情中查看该项目的原文、来源及检查时间。
5. 后续使用“重新检测”“更新我的 X 情报”或“删除配置”。删除会清除当前访客的密钥、个人结果并取消旧任务。

同一浏览器的身份会话有效期为 30 天，访问个人接口续期；换浏览器或清除 Cookie 后需要重新配置。检测和抓取会消耗 X API 额度。个人动态覆盖库内最多 40 个官方账号、每账号最多 10 条近期推文，不自动改变公共领取状态、评分或教程。

## 本机验证范围

- 独立 Cookie 会话、过期、认证加密及文件权限。
- 真正的账号和推文读取路径；受控响应覆盖认证、权限、额度、限流、超时、损坏响应、空结果等分支。
- 同源写请求检查、非法输入、无密钥状态响应、两访客隔离。
- 删除或替换后旧任务不得写回，重复启动合并，全后台最多两个任务，部分及完全失败保留上次结果，后台重启标记中断。
- 实际 Chromium 桌面 1440×900、手机 390×844 验证设置入口、自动抓取、抓取时重新检测、刷新保留、错误保存、删除竞态、列表失败仍能进入设置和静态后台缺失降级。
- 浏览器无页面异常，手机无横向溢出；样例凭据不进入 localStorage 或 sessionStorage；私有 URL 无法访问；个人请求前后公共数据主文件哈希相同。

浏览器验收入口为 `scripts/api/check-browser.ts`，只注入测试用 X 客户端，不提供生产模拟开关、不发送真实付费请求。截图在 `.cache/x-api-check/`。本机 Playwright 包期待的浏览器版本与已有缓存不同，运行验收时通过 `PLAYWRIGHT_EXECUTABLE_PATH` 指向已有 Chromium，无需下载浏览器。

## 独立审查与修复

唯一实际独立审查使用 GPT-6.1-sol；首次 GPT-6-astra 调度因额度限制未运行。无 Critical 或 Minor，三项 Important/P2 均以新测试先复现失败，再修复通过：

1. 满额时替换密钥：新 generation 清除旧任务状态，成功缓存及原时间保留；自动启动失败后可重试，重试成功清除启动失败提醒。
2. 检测失败后刷新：持久化的检测失败优先于历史抓取成功；任务终态和配置状态一起读取，避免中间状态覆盖。
3. 损坏 HTTP 200：用户 ID 必须是字符串，显式 null 推文结果不能被当成合法省略的空结果。

最终完整回归 563/563；浏览器新增“已保存凭据检测失败后刷新”的路径通过。真实 X、线上部署及此前 P0/P1/P2 的全面代码重审不在本次独立审查范围。
