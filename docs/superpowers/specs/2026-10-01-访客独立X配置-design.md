# 访客独立 X API 配置与更新设计

日期：2026-10-01。状态：聊天中的方案已确认；本文待用户审阅，尚未进入实现。

## 目标与已确认范围

在页面右上角增加“设置”，进入中文二级页面。每位访客可以申请、配置和检测自己的 X API；检测通过后启动抓取，完成后自动加载该访客可见的最新项目方 X 信息。

配置、检测和抓取在本机先完成实现及验证。线上采用前后台同域部署；GitHub Pages 单独运行时不能提供密钥管理和个人抓取能力。没有真实有效凭据时，不宣称真实 X 接入已验收。

访客身份以同一浏览器的独立会话识别，配置可在页面刷新及服务重启后继续使用。更换浏览器、清除身份 Cookie 或会话到期需要重新配置。会话有效期为 30 天；访问设置或个人抓取接口时续期。删除配置会清除密钥和个人抓取缓存，并使旧任务不能再次写回结果。

## 当前代码事实与必要调整

- `src/components/Layout.tsx` 提供顶部导航，`src/lib/router.ts` 使用 hash 路由；设置沿用这套结构。
- `src/lib/refresh.ts` 的触发能力依赖构建期 URL；没有后台时只能重新读取静态 JSON。
- `scripts/pipeline.ts` 写入共用 `data/`，不能直接用访客凭据启动它，否则个人请求会改写全站数据。
- `scripts/fetch/twitter.ts` 当前会将 API 读取失败降级为账号探测，也只输出账号和信号数量，未保存命中推文正文。这条路径不能作为凭据有效或个人情报已更新的证明。

因此保留公共数据流水线，新增独立的访客 X 抓取及缓存路径。必要调整集中在设置、X 访问、个人结果展示和刷新能力，不重写现有评分、教程或公共抓取逻辑。

## 页面与用户流程

### 入口和说明

“设置”放在顶部“我的关注”右侧，与当前导航风格一致；窄屏也可直接进入。设置页面使用 `#/settings`，列表数据加载失败时仍可进入。

页面提供返回空投列表的入口，以及以下中文说明：

1. 打开 X 开发者控制台，登录并完成开发者账号申请。
2. 点击 New App（新建应用），填写应用用途并创建应用。
3. 取得 Bearer Token（读取公开信息的访问凭据），粘贴到本页。
4. 在 X 控制台确认可用额度并设置消费上限，点击“保存并检测”。

说明链接采用官方文档，并提示检测和抓取会产生 API 调用，X 按用量计费。只要求 Bearer Token，不要求登录密码、钱包信息或额外的 API Key/Secret。

### 配置操作

输入框默认遮挡内容，可切换显示；已保存的密钥不回显，也不在浏览器持久化。配置完成后只展示“已配置”、最近检测时间及结果。

- **保存并检测**：对新输入的凭据完成真实检测；通过后替换保存的配置，并自动启动个人抓取。失败时保留原配置，提示修改新输入。
- **重新检测**：使用后台已保存的凭据检测，不重复保存，不自动启动全量抓取。
- **更新我的 X 情报**：使用检测通过的配置启动抓取；任务运行时显示进度，重复点击不重复启动。
- **删除配置**：删除该访客密钥及个人结果，恢复公共数据视图。

修改输入会清除该输入对应的旧检测提示，避免用户误把上次成功状态理解为新输入已通过。

### 状态与检测口径

状态明确区分：未配置、检测中、检测通过、检测失败、抓取中、部分抓取成功、抓取完成、抓取失败。

检测针对一个库内官方账号发起账号查询和近期推文读取。两项接口都成功才表示配置可用；成功返回空列表表示读取权限正常但没有近期可读推文，不伪造内容。

错误提示区分凭据被拒绝、读取权限不足、额度不足、调用频率限制、账号不存在、网络超时和服务暂不可用。分类依据真实 HTTP 状态及官方错误类型；无法确定的错误明确表示无法判断，不统一归因于网络。不使用 oEmbed 成功替代推文接口检测。

## 后台、密钥和隔离

新增 Node 后台，本地仅监听回环地址，开发页面通过同源代理调用；生产后台同时提供构建后的静态页面及 `/api/` 接口，HTTPS 由部署入口提供。

访客身份使用后台生成的高熵随机会话 Cookie，设置 HttpOnly、SameSite；生产启用 Secure。所有配置、任务和结果从 Cookie 解析所有者，不接受请求参数指定其他访客身份。

密钥使用服务器主密钥进行认证加密，保存在非公开目录，文件权限仅允许运行用户读取。生产主密钥由环境变量提供，本地首次运行可生成并保存在私有目录；不进入 Git、构建产物或日志。静态服务和 Vite 显式禁止读取私有目录。主密钥丢失时提示重新配置，不尝试明文降级。

配置变更接口校验同源请求和请求类型；跨站调用不得保存、删除配置或启动付费抓取。响应和日志不得包含 Token、Authorization 请求头或原始上游错误正文。

匿名会话过期时停止接受其私有操作，清除过期文件。个人缓存只对所属会话提供，响应使用 `Cache-Control: no-store`。配置版本随替换或删除变更；任务写入前检查版本和会话有效性，避免旧任务覆盖新配置或恢复已删除数据。

最小接口如下，路径以最终实现为准，业务语义固定：

| 接口 | 用途 |
| --- | --- |
| GET `/api/x/settings` | 获取当前访客的配置状态、检测状态、后台能力及任务摘要，不返回密钥 |
| POST `/api/x/settings` | 检测新凭据，通过后保存并启动抓取；失败不覆盖原配置 |
| POST `/api/x/test` | 检测该访客已保存凭据 |
| DELETE `/api/x/settings` | 删除配置、缓存并使旧任务结果失效 |
| POST `/api/x/refresh` | 启动或返回正在运行的个人抓取任务 |
| GET `/api/x/result` | 获取该访客的任务进度、最近成功数据及本轮错误 |

检测按访客设置短期冷却，抓取按访客串行执行且限制后台总并发；认证、额度或全局限流错误停止后续请求。服务重启时将未完成任务标记为中断，保留上次成功结果，允许手动重试。

## 数据与刷新语义

公共项目库仍由现有流水线维护。个人抓取仅查询库内已有官方账号，按账号去重，沿用当前最多 40 个账号、每账号最多 10 条近期推文的边界；页面说明本轮覆盖范围。检测的样本请求不等于这 40 个账号都抓取成功。

个人结果保留项目 slug、账号、推文 ID、原文、来源链接、发布时间和实际检查时间。按现有空投关键词标注候选线索，不能把关键词命中自动认定为已确认空投或开放领取，也不自动改变公共项目评分和操作教程。

列表提供“我的 X 最新动态”区域，项目卡片和详情可查看该项目的个人动态。原文可能是英文，明确标记“推文原文”；本次不新增机器翻译服务。公共项目库的更新时间和个人 X 检查时间分别显示，不用个人抓取时间改写公共数据的新鲜度。

抓取流程为：提交任务 → 轮询个人任务 → 成功后加载个人结果及当前公共数据 → 展示实际结果。结果为空、未命中关键词、部分账号失败和内容没有变化均如实说明。

未访问成功的账号保留该访客上次成功的数据及原检查时间，标明本轮未更新；本轮完全失败则保留完整上次成功缓存。新结果在完成并校验后原子替换，不能让半成品进入页面。

没有后台的静态部署仍可浏览公共项目库；设置页面明确显示此部署不支持 API 配置，禁用提交，不在浏览器保存密钥。已接入后台时，公共“重新加载数据”和个人“更新我的 X 情报”保持清楚的用途区别。

## 验收标准

1. 桌面和窄屏均可从右上角进入设置，页面文案及操作提示为简体中文。
2. 无效 Token、仅账号接口成功、额度不足、限流、网络超时不能显示配置检测成功；失败保存不覆盖已有有效配置。
3. 成功保存可自动启动任务，运行中有进度，完成后无需整页手动刷新即可看到真实来源信息；任务完成但无新线索有明确提示。
4. 两个浏览器会话的配置、任务和结果完全隔离；访客请求不能指定另一会话的所有者。
5. 原始 Token 不出现在设置状态响应、浏览器持久化、日志、Git、构建产物或可公开访问的文件中；跨站写操作被拒绝。
6. 重复点击不重复启动任务；配置替换、删除或会话过期后，旧任务不能重新写回结果；服务重启后的中断可识别和重试。
7. 部分和完全失败均保留最后成功结果及原时间；个人抓取不修改公共 `data/`，不更改公共领取状态、评分和教程。
8. 自动化测试以可控 X 响应覆盖成功、空结果和失败路径；执行相关测试、类型检查、生产构建，并通过浏览器核验桌面、窄屏和原有主要页面。
9. 真实有效 Token 未提供时，明确报告真实 X 检测及抓取未验收；线上后台未部署时，明确报告线上接入未验收。
