## 后续维护

人工核验后，在 `data/seed/official-profiles.json` 的对应项目 `evidence` 中记录具体页面。网站归属使用 `official_website`，具体活动公告使用 `official_announcement`，具体操作教程使用 `official_guide`。仅把 `verified` 改成 `true` 不会获得已核实结论。

核验记录形态如下。示例字段必须替换为实际核验内容，不能直接当成真实证据使用：

```json
{
  "type": "official_announcement",
  "url": "https://project.example/announcement",
  "label": "具体活动公告",
  "verified": true,
  "activity_status": "confirmed",
  "verification": {
    "method": "manual_review",
    "source_url": "https://project.example/announcement",
    "checked_at": "实际核验时间的 ISO 格式",
    "note": "具体核对了哪些官方归属及活动阶段信息，并摘录关键依据"
  }
}
```

官网核验链接必须与项目当前入口完全一致；教程核验链接必须与具体步骤来源一致。旧公告不能覆盖更新后的矛盾来源。金额需要人工估算时，在项目详情的 `cost.basis` 中保存 `manual_review`、来源、时间和说明；未确认的金额继续保持 `null`。

安装依赖并准备 Node.js 后，可在当前项目目录执行 `npm run repair:p0` 离线重建；随后执行 `npm run validate` 和 `npm run build`。联网抓取仍使用原有 `npm run pipeline`，它与离线修复共用最终生成规则。本次没有运行联网抓取，外部网站的当前真实性、金额和活动期限仍需实际核验。

完整中文化、译文纠错、教程广告清理及 UI 布局优化属于原审查中的后续事项，本次未扩大实施范围。
